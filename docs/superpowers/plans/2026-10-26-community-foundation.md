# Community Foundation — No Account Setup Required

**Goal:** Build a usable first community interface and Cloudflare-ready backend foundation entirely in the repository, requiring no user account, secrets, external resources, or deployment now.

**Design:** The existing planner community tab opens a real community screen rather than Coming Soon. It has public-updates and personal-device-drafts views, category filters (fare, detour, timing, tip, route correction), search, clear empty/loading/error states and an inline composer. Composer selects an exact policy-allowed directional route via searchable suggestions showing endpoints; no default route. Save/edit/delete drafts locally with timestamp and plain text. Drafts never appear as public posts or get votes/authors. Clearly state saved on this device, not published. Anonymous browsing remains possible. Real login/public posting/comments/votes are deferred until service configuration; no fake credentials or local fake authentication.

**Architecture:** New local storage key and schema-versioned validated bounded drafts. Do not read the old prototype's seeded localStorage key as real reports; leave old key untouched. Storage access failures/corrupted values handled without crashing or falsely claiming persistence. Route names may be shown from actual route records; exact routeId drives map selection. Missing/held route drafts remain readable but cannot open a substituted route. Plain React text only, no HTML rendering or location/password collection. Preserve all existing dirty work and routing datasets.

**Cloudflare foundation:** Pages Functions under functions/api/community for capabilities and read-only approved-post listing. D1 schema migration for users, reports, comments, votes/moderation with constraints/indexes, not auto-applied anywhere. Capabilities explicitly auth=false/publishing=false; write requests fail closed with JSON503 until authentication/moderation integration. Database binding absent -> honest service-unavailable response, never fabricated sample data. Approved-only projection, bounded pagination/category/search and parameterized queries; no user emails/provider IDs/public draft bodies leakage. Pure server handlers with injectable fakeD1 tests. No provider selection or auth SDK yet, no secrets or fake resource IDs in config. Future binding name COMMUNITY_DB documented. Local Vite does not run Pages Functions: frontend must safely recognize unavailable/non-JSON endpoint and remain usable for drafts.

API GET /api/community/capabilities returns { authenticationAvailable:false,publishingAvailable:false }; GET /api/community/posts accepts category (ALL/fare/detour/frequency/tip/route), q and cursor/limit, returns {posts:[],nextCursor:null} shape only when DB actually available; absentDB503 with code. Each post {id,routeId,category,body,createdAt,authorDisplayName}. No user name default invented; generic withheld author is okay from actual profile. Reject writes503 consistently. Reports remain pending until moderation when future writes enabled. No downloads/user setup/deploy required.
